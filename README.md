# NASA Hackathon 2026 - Project Earth 



Project name:
Signal & Noise

Summary:
Signal & Noise is a web tool that lets anyone test whether a climate trend is real or just noise. Users ask a question such as “Is Dallas getting hotter from 2000 to 2025?” and an intake assistant suggests the variable, place and time period. A statistics engine then analyzes NASA data (GISTEMP v4, POWER/MERRA-2, Blue Marble, Sentinel-2) and returns a rate per decade, a 95% confidence interval, a sample size and a verdict backed with statistical analysis to state if it is significant or “not proven”. 

It addresses the Earth System Trend Detective challenge by turning raw NASA records into transparent, defensible trend detection. It uses autocorrelation-aware tests, a second-opinion check and multiple-comparison correction across the map from mathematical analysis. 

It matters because climate claims are often cherry-picked or over-read. By labeling weak evidence honestly, it helps users separate signal from noise.


Project Details:
Signal & Noise is a web tool that lets anyone investigate a climate question about a specific place, such as "Is Dallas getting hotter from 2000 to 2025?" An intake assistant turns the plain-language question into measurable variables (warming, rainfall, soil wetness or solar radiation), a location and a time window. A statistics engine then runs on a cached NASA record and returns a rate of change per decade, a 95% confidence interval, the sample size and a clear verdict. The verdict is either "significant" or "not proven." Trends are fitted with ordinary least squares using Newey-West HAC standard errors, and Sen's slope with a Mann-Kendall test (with the Hamed-Rao autocorrelation correction) provides a second opinion. A case is called significant only when both methods agree. Map-wide results use Benjamini-Hochberg FDR correction, and any record with fewer than 20 annual values is labeled exploratory. Every case file includes a "show your work" panel, and the AI only proposes questions and explains results; it never does the arithmetic, because every number is computed by the code.
The main benefit is that non-experts get a defensible answer in seconds, with the uncertainty and the method fully visible. Weak evidence is stated honestly rather than being drawn as a confident-looking line, which makes the tool useful for people who need to understand climate data but don't have a statistics background. The intended impact is to reduce cherry-picked and over-read climate claims, and to help students, journalists, educators and local decision-makers tell real trends from noise before they act on them or repeat them to others.
To build it, we used a range of NASA and partner datasets: NASA GISTEMP v4, NASA POWER (MERRA-2), NASA Blue Marble, Sentinel-2 L2A via Microsoft Planetary Computer, NASA Earthdata and Meteomatics. The frontend is written in JavaScript, HTML and CSS, with Three.js and a globe library powering the interactive map. The statistics and data processing are done in Python using NumPy, SciPy, statsmodels and pymannkendall. The project is hosted on GitHub Pages and is open source on GitHub, and it works on all screen sizes, though a laptop or tablet gives the best experience.
What makes the project creative is that most trend tools simply show a line going up or down, whereas ours treats the verdict as the product. It uses a case-file format, an interactive globe for exploring cities, trend fields and ocean cells, and a clear "not proven" state that is presented as a legitimate and useful outcome rather than a failure. We also made a deliberate design choice to strictly separate the AI, which explains, from the statistics, which decide, and this keeps the output trustworthy.
Our team considered several factors along the way. On statistical validity, we dealt with autocorrelation, multiple comparisons and short records through HAC errors, a second independent test and FDR correction. In honesty, we avoid any causal claims and make clear that "not proven" is not the same as "no trend." We also accounted for data limits, such as GISTEMP anomalies using a 1951-1980 baseline while POWER values are absolute. For transparency and reproducibility, results are computed in code from cached NASA data with the sources and method always visible. Finally, we prioritized accessibility by producing plain-language output that people without a statistics background can understand.
